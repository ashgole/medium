## 🎯 The Writing Philosophy

All articles in this repository strictly adhere to our core writing standards:

### 1. 100% Human Language
- **Talk Like a Peer**: Written like an experienced senior engineer chatting with a colleague over coffee.
- **Ditch Robotic Jargon**: Plain English explanations before introducing formal terminology.
- **Relatable Analogies**: Anchoring abstract ideas in everyday models (backpacks, restaurants, filing cabinets).
- **Short & Scannable**: Concise paragraphs (3–4 sentences max), clear headings, and bullet points.
- **5 to 10-Minute Read**: Focused, high-density learning (~1,000 to 2,000 words) with zero fluff.

### 2. Mandatory Framework: What, When, Why, Example
Every article follows this strict 4-part structure:

1. **What**: Plain-English definition and an intuitive real-world hook or analogy.
2. **When**: Specific real-world scenarios for when to use it, plus when **not** to use it.
3. **Why**: The problem it solves, motivation, pros/cons, and under-the-hood engine mechanics.
4. **Example**: Concrete, runnable code showing progressive difficulty and explicit comparisons (`// ❌ Anti-pattern` vs. `// ✅ Recommended`).

## 🛠️ Contribution & Authoring Guidelines

When contributing a new article or guide:

1. Place the Markdown file in its relevant topic directory (e.g. `reactjs/custom-hooks.md`).
2. Follow the mandatory 4-part structure: **What, When, Why, Example**.
3. Use modern ES6+ syntax and verify that all code snippets are runnable and self-contained.
4. Review the workspace rules in [`.agents/rules/rule.md`](./.agents/rules/rule.md) before publishing.
